# Trace

Trace is a small text language for diagrams. You write plain text; it is drawn like a careful
hand would lay it out. The rendered cases in `examples/cases/` are the quality bar: when in doubt
about how something should look, follow the style rules below and look at those.

The project started in a claude.ai conversation. Everything decided there is captured in this
file and in `docs/`. Read `docs/layout-guide.md` before drawing or restyling a case (it is the checklist for making a diagram look right), `docs/language.md` before changing the parser, `docs/architecture.md`
before changing layout, and `docs/roadmap.md` before picking up work. `docs/drawing-rules.md` lists the rules for a good diagram learned from reviews: add to it when a review leads to a change.

## Layout of the repository

- `src/trace.js`: the whole engine in one file: parser, layout (via ELK), SVG renderer.
  CommonJS export at the bottom, and plain globals when inlined in a page. Splitting it into
  modules is on the roadmap; keep both entry styles working when you do.
- `src/lucide-core.js`, `src/lucide-names.js`, `src/lucide.js`: icon data generated by `npm run build:icons`
  from the `lucide-static` dev dependency (ISC licence in `third-party/lucide-LICENSE`). Core = the named
  icons, bundled in pages; names = every Lucide name, bundled; full set = Node only, pages fetch other
  icons on demand. Never edit by hand; to name a new common icon, add it to `CORE` and `ICON_ALIASES`.
- `src/logo-core.js`, `src/logo-names.js`: technology logos generated by the same `npm run build:icons` from the
  `simple-icons` dev dependency (CC0, `third-party/simple-icons-LICENSE`; the logos are their owners' trademarks).
  Core = the common logos, bundled in pages; names = every logo name, bundled; Node takes any other from
  `simple-icons`, pages fetch it. To bundle another, add it to `LOGO_CORE` in `tools/build-icons.js`; short
  names live in `LOGO_ALIASES` in `src/trace.js`.
- `examples/playground/*.trace`: the examples shown in the playground, among them `icons.trace`.
- `examples/cases/*.trace`: twenty real-world diagrams in their *full* form (icons, rows and columns,
  span and bridge, reversed links), with notes in `cases.json` (what Trace uses, what is still missing).
  `examples/cases/simple/*.trace` are the same diagrams as you would write them with no layout help,
  generated from the full ones by `npm run simplify` (`tools/simplify.js`); a test fails when they are
  out of date. Together they are the regression suite and the showcase.
- `examples/holdout/`: real diagrams from public C4 and Mermaid sources, adapted to Trace with no layout help;
  the held-out check for layout rules (`npm run metrics`, `tools/metrics.js`). Each has its Mermaid version
  (`.mmd`); `npm run build:compare` draws both in `dist/compare.html`. Mermaid sources are converted with
  `tools/mermaid-to-trace.js`. Sources and licences in its README.
- `examples/features/`: one small before/after pair per language feature (`<id>.before.trace`, `<id>.after.trace`) and the text
  in `features.json`; `npm run build:features` draws them in `dist/features.html`. A feature can switch an automatic tidy-up off
  for its "before" (`beforeOff`: `fold`, `merge`, `tidy`), which is what `compile(..., { off: [...] })` does.
- `playground/template.html`: the live editor page. `playground/showcase-template.html`: the page that draws the cases
  with their notes. `playground/features-template.html`, `playground/compare-template.html`: the features and
  comparison pages. All get the icon and logo data and `src/trace.js` inlined by the build.
- `tools/`: `build-playground.js`, `build-showcase.js`, `build-features.js`, `build-compare.js` (the pages, to `dist/`),
  `build-icons.js` (icon and logo data), `render.js` (one file to SVG or PNG), `snapshots.js` (all examples to `out/`),
  `simplify.js` (the simple forms), `metrics.js` (layout quality), `mermaid-to-trace.js` (Mermaid to Trace, plainly),
  `measure.js` and `png.js` (text widths and PNGs in Node).
- `test/examples.test.js`: every example lays out with no errors, no overlapping nodes, no frame covering a node
  that isn't its own, no link through a node, no two links on top of each other, no slanted link; plus a test per
  feature (`test/fixtures/` holds the scenarios that are not examples).

## Commands

```
npm install
npm test                 # parse + layout + invariants for every example
npm run simplify         # regenerate examples/cases/simple/ from the full cases
npm run snapshots        # out/**/*.svg, plus .png if @resvg/resvg-js installed
npm run build            # dist/: playground, showcase, features and compare pages
npm run build:icons      # src/lucide-*.js and src/logo-*.js from the dev dependencies
npm run metrics          # layout quality, compared with metrics/baseline.json (-- --save to update it)
node tools/render.js examples/cases/dmz.trace out.svg     # also out.png, --dark, --zoom 2, --watch
```

## How to work on layout

Layout changes have side effects across diagrams. After any change to `src/trace.js`:
run `npm test`, run `npm run snapshots`, and look at the PNGs of every example, not only the one
you were fixing. Most bugs found so far were only visible in a picture (a frame swallowing a
node, a title under a box, a jog in a link). If you add a feature, add or extend an example that
uses it.

Then run `npm run metrics`. It measures the examples (where the rules are tuned) and `examples/holdout/`
(real C4 and Mermaid diagrams adapted to Trace, never tuned on) and compares with `metrics/baseline.json`: links
through or brushing nodes, overlapping links, crossings, bends, links along borders, crossed labels, overlaps. A
layout change is kept only if it does not make the held-out set worse; save a new baseline with
`npm run metrics -- --save` when you commit it. Never edit a held-out diagram to suit the engine.

Node measures text with an approximate width table (`tools/measure.js`); the browser measures
with canvas and Inter. Snapshots are therefore close to, not identical with, the browser.

## Style rules (from the reference SVGs)

- Palette and classes are fixed in `PALETTE` and `diagramCSS()`; output must work in light and
  dark (`prefers-color-scheme` in the standalone SVG, page theme in the playground).
- Node label: bold 13px name, muted 11px note under it. Edge labels: muted 11px with a halo.
- Orthogonal links with 7px rounded corners; arrowheads end just short of the box.
- Semantic kinds, not colours: box, store, engine, state, pill, ask, start, final; tags ok, bad,
  dashed, muted; frames green, blue, orange, purple, grey.
- Orthogonal links only; where two cross, the horizontal one hops over the vertical one.
- Icons in the ink colour; technology logos in one colour too (ink in the icon's place, the note's grey when
  small beside the technology's name), never brand colours. Marks and concentrator bars likewise.
- Restraint: no shadows, no gradients, no colour without meaning.

## Naming

The name is Trace, without an accent (it was briefly “Tracé”). The npm name `trace` is taken;
the package is `trace-diagrams`, files use `.trace`.

## Conventions

- Error messages tell the person what to write instead, and carry a line number.
- UI text uses typographic apostrophes and quotes; code and syntax keep straight ones.
- Don't add dependencies to the engine beyond elkjs without a reason; pages load elkjs 0.9.3 as a
  UMD script from jsDelivr, pinned. The comparison page also loads Mermaid 11.17.2 the same way (older
  releases cannot read the `align` lines of the Mermaid architecture examples).
