Routing and fallback

docs/architecture/routing-and-fallback.md

Refusals and failures red. The two "next attempt" ends stop there, as in the source; the text implies a loop back.

Current Mermaid, for comparison
flowchart TD
    A[Job created] --> V{validate: grant, pair, pinned backend, never}
    V -->|refused| R1[Request refused 403 415 422]
    V -->|ok| C[candidates: order, filter, live workers only]
    C --> F{any candidate}
    F -->|none| R2[503 no-backend-available, nothing is stored]
    F -->|some| Q[Attempt 1 on the first candidate]
    Q --> X[Attempt ends failed]
    X --> T{error type transient}
    T -->|yes| M{same backend tried at most max_retries times and still a candidate}
    M -->|yes| Q2[Next attempt on the same backend]
    M -->|no| B{fallback enabled}
    T -->|no| B
    B -->|no| J1[Job fails]
    B -->|yes| N{a candidate not yet tried}
    N -->|yes| Q3[Next attempt on the first such candidate]
    N -->|no| J1

A lost lease, step by step

docs/architecture/job-lifecycle.md · sequence

Source error kept for now: it shows the outputs uploaded to and deleted from Postgres; they are S3. The docs version adds S3 as a participant.

Current Mermaid, for comparison
sequenceDiagram
    participant A as Worker A (slow)
    participant DB as Postgres
    participant S as Sweep (any worker)
    participant B as Worker B
    A->>DB: claim, attempt 1 running, lease set
    Note over A: keep-alive stalls, lease passes
    S->>DB: lock job then attempt 1, lease still expired
    S->>DB: attempt 1 failed (lease lost), attempt 2 queued
    B->>DB: claim attempt 2
    A->>DB: renew_lease returns false, lost flag set
    alt run ended before the loss was seen
        A->>DB: upload to out/1, complete_attempt refused
        A->>DB: delete out/1 (orphan if this fails)
    else lost already set
        A->>A: drop outcome, no upload
    end
    B->>DB: complete_attempt for attempt 2, job succeeded

Idempotency: two requests, one key

docs/architecture/idempotency.md

Columns reordered (S3, request 1, Postgres, request 2) so no arrow crosses a lifeline; answers dashed.

Current Mermaid, for comparison
sequenceDiagram
    participant R1 as Request 1
    participant R2 as Request 2 (same key)
    participant DB as Postgres
    participant S3 as S3
    R1->>DB: reserve, insert key with hash, no job, commit
    R2->>DB: reserve, conflict, select for update
    DB-->>R2: same hash, no job, heartbeat fresh
    R2-->>R2: InProgress, 409 with Retry-After 2
    loop while request 1 uploads
        R1->>DB: heartbeat_at = now()
    end
    R1->>S3: put inputs under jobs/id
    R1->>DB: one transaction: job, attempt, attach job to key
    R2->>DB: retry with the same key
    DB-->>R2: Replay of the job
