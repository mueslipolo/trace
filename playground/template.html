    Syntax

    Nodes

    api: FastAPI app | and Router
store pg: Postgres
ask ok: any candidate?
failed [bad]: Job failed

    Name, then a colon, then the bold label; text after | becomes the muted note. Kinds: box (default), store, engine, state, pill, ask, start, final. Tags: [ok] [bad] [dashed] [muted]. Use \n to break a line. A word that is not a tag adds an icon: fw [firewall]: Edge, db [database top]: Orders (top puts it above the text); see Icons below.

    Links

    client -> api : HTTPS, API key
ops --> api : no auth
pg <- worker : claim, lease
a -> b -> c
x -> y [bad] : refused

    --> is dashed, <-> has two heads, -- none. ==> is the main path (thicker), -x a refused link (a cross at the target). pg <- worker draws the arrow into pg but places worker after it: the way to put a node on the far side.

    Grouping

    frame api "api process" [blue] {
  router: Router
}
column {
  store pg: Postgres
  store s3: S3
}

    A frame draws a titled zone (green, blue, orange, purple, grey). A column stacks nodes top to bottom, a row side by side; links inside them run straight. Side-by-side columns of the same length line up row for row.

    Sequence diagrams

    sequence
client -> api : POST /jobs
api --> client : 202
note over api, db : one transaction
loop "every 5 s" {
  worker -> api : claim
}

    The line sequence makes time run down. Participants run across the top in the order you mention them; -> is a message, --> a reply, a -> a a message to yourself. note over/left of/right of, and loop, alt (with else), opt, par groups. See the two examples.

    Whole diagram

    direction down
spacing 1.3
title "Job states"
key box [dashed] : planned
key -> [bad] : failure path

    direction is right (default) or down. Nodes keep the order you write them in, so reordering lines reorders the drawing. # starts a comment.
