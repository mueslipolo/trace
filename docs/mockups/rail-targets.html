Rail targets: what "an ordinary node" means

Today the node a rail feeds can only be declared inside the rail, so it exists in a world of its own. An ordinary node is any node you declare anywhere, like the others: in a zone, in the middle, with normal links in and out. The rail becomes only the bus: it names the node it ends at, and the node stays where the flow puts it. Hand-drawn mockups, nothing is built yet.

What changes, and what does not

  • Placement: the target is placed by the layout like any node. The bus does not take part: it is drawn afterwards along the outer edge on the side you name, and turns in to reach the target (crossing at most one border).
  • Taps stay as they are: a link to the rail's name, from any node, anywhere.
  • Old form keeps working: rail logs [right] { siem: SIEM } is a rail with a target declared inline, exactly as now.
  • New form: rail logs [right] -> siem. One rail, one target; several rails may share a target (3); a target may also have ordinary links (1, 4).
  • Limits that remain: a rail still names one outer side; a target on the far side of the diagram needs a bus that runs the whole length (it still avoids nodes: it runs outside everything), and a target with no free side gets the bus on its nearest side.

0 Today: the target exists only inside the rail

The SIEM is declared inside the band. It is not part of the diagram: no normal links, no zone of its own, nowhere to be but the outer edge.

rail logs [right] {
  siem: SIEM
}
fw1 -> logs
fw3 -> logs

1 An ordinary node, in a zone, with its own links

The SIEM is declared like any node, inside the management zone, and keeps its normal links (it alerts the pager). The bus runs along the edge of the diagram and turns into the zone to reach it, crossing the zone border once.

frame mgmt "management" [purple] {
  pager: Pager
  siem: SIEM
}
siem -> pager
rail logs [right] -> siem : 514/udp
fw1 -> logs
fw3 -> logs

2 An ordinary node in the middle of the diagram

The target is in the heart of the picture. The bus is one line that runs the full height beside the diagram, and enters the zone at the target's height from both directions. Taps from above and below meet there.

frame ops "operations" {
  alerts: Alerts
  monitor: Monitor
}
monitor -> alerts
rail metrics [right] -> monitor
gw -> metrics
app -> metrics

3 Two rails, one target

Logs and metrics both end at the same Observability node, on different sides of its edge or at different heights. Each rail keeps its tint; where they would meet, they run in parallel and hop.

rail logs [right] -> obs
rail metrics [right] -> obs
fw1 -> logs
fw3 -> logs
app -> metrics
db -> metrics

4 A target that also has an ordinary link into it

`app -> siem` is an ordinary link that takes part in the layout; the bus is the extra, light line that arrives from the other side. Today this needs the SIEM to be two things at once, which Trace cannot do.

siem: SIEM
app -> siem : audit events
rail logs [right] -> siem
fw1 -> logs
fw3 -> logs
