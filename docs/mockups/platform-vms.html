With VMs: one collector per zone

With Kubernetes one collector stands for the whole cluster. With VMs there is an agent on every machine, and in practice a collector (a log forwarder, an aggregator) per network zone, because the firewalls only let that one machine talk out. So the picture has two tiers and only the second is drawn.

How it reads

  • Tier 1, on every VM: an agent, not drawn as a node. It is a dot on the VM (a node tag). The legend says what it is. Twenty VMs cost twenty dots, not twenty arrows.
  • Tier 2, one collector per zone: a node. It is where the arrow leaves the zone, so it is where the firewall rule is: one flow, one port, one label per zone. That is the information a network reviewer wants.
  • Central: the gateway collector in the observability zone receives from all of them and feeds Loki and Tempo.
  • If a zone has no collector (a single flat network), the VMs' dots are all there is, and the arrow comes from the zone itself: dmz -> gw : 4317 (a link from a frame).

What it needs from Trace

Nothing for the picture itself: zones, a collector node per zone, plain links between zones. The only new thing is the dot on each VM: a node tag (here agent) that draws a small coloured dot and appears once in the legend. Without it the same note can go in the node's text (web-01 | agent).
